================================================================================
1. WHY SDK 54, SPECIFICALLY
================================================================================

This project is deliberately pinned to Expo SDK 54 (React Native 0.81,
React 19.1). The  development structure for this codebase says so
explicitly: "Never upgrade Expo SDK... Always remain compatible with
SDK 54." That instruction stands until a future phase explicitly revisits
it.

Practical reason this is easy to stick to right now: as of mid-2026,
`npx create-expo-app@latest` still scaffolds new projects on SDK 54 by
default, even though newer SDKs exist -- Expo has kept new-project
generation on SDK 54 for a period while Expo Go's App Store/Play Store
listings catch up to newer SDKs. This is why running create-expo-app
today still gave you `expo ~54.0.x` in package.json.

================================================================================
2. WHERE SDK 54 SITS IN THE EXPO TIMELINE (as of July 2026)
================================================================================

Expo ships roughly 3 SDKs a year (historically); this is the actual
released sequence as of today:

  SDK 54  -- Sept 2025  -- React Native 0.81, React 19.1
             Final SDK to support the Legacy (old) Architecture.
             This is what TRU Connect mobile targets.

  SDK 55  -- ~March/April 2026 -- React Native 0.83, React 19.2
             New Architecture becomes MANDATORY (Legacy Architecture
             removed entirely; "newArchEnabled" config option removed).
             Default project template switched from `app/` to `src/app/`
             folder structure. Introduced the Native Tabs API.

  SDK 56  -- May 21, 2026 -- React Native 0.85, React 19.2
             Expo UI (SwiftUI/Jetpack Compose universal components)
             promoted to stable. Hermes v1 is now the default JS engine.
             Expo Router dropped its dependency on React Navigation
             internally. Big native-module call-overhead improvements
             on iOS (new JSI layer).

  SDK 57  -- June 30, 2026 -- React Native 0.86, React 19.2 (unchanged)
             Deliberately small, non-breaking release -- signals a shift
             toward a steadier, lower-churn release cadence going forward
             (Expo's own stated goal: fewer breaking upgrades per year).
             This is the CURRENT latest stable SDK as of this writing.

Net effect: SDK 54 is two major SDKs behind current, but it is still
officially supported with critical fixes until the next SDK ships
(expected ~Sept/Oct 2026), and it's still what new projects get by
default. There is no urgency to move off it for this phase of TRU Connect.

================================================================================
3. WHEN (AND HOW) TO EVENTUALLY UPGRADE
================================================================================

Do not upgrade mid-Phase-1. When the team does decide to move to a newer
SDK (likely SDK 56 or later, skipping 55's mandatory New-Architecture-only
transition deliberately rather than accidentally), the safe sequence is:

    1. Read the official upgrade guide for the target SDK:
       https://docs.expo.dev/bare/upgrade/ (or the in-app "Upgrading Expo
       SDK" doc for the version you're targeting).
    2. In frontend/mobile:
           npx expo install expo@^57 --fix
       (replace ^57 with whatever target SDK you're moving to)
    3. Re-run:
           npx expo-doctor
       and resolve anything it flags before proceeding.
    4. Note two structural differences you'll hit if you land on SDK 55+:
       - New Architecture is mandatory from SDK 55 onward; the "Legacy
         Architecture" escape hatch this project could theoretically fall
         back to on SDK 54 will no longer exist.
       - Expo's own default template moved from `app/` to `src/app/` in
         SDK 55. TRU Connect's architecture is intentionally different
         from that (routing lives in a top-level `app/`, separate from
         `src/`) -- this was a deliberate project decision, not something
         that needs to be reconciled with Expo's own default when you
         read newer Expo documentation and see `src/app/` mentioned there.

--------------------------------------------------------------------------------
Never use plain `npm install` for these. Expo's installer checks its own
compatibility table for your exact SDK version and picks the right
version automatically -- plain npm has no idea what version of these
native packages is safe for SDK 54.

                                    (app/index.tsx)

    npm ls expo-router

6. INSTALLING EXPO WITHOUT THE DEMO FILES
================================================================================

`npx create-expo-app@latest .` (no --template flag) gives you the full
default template: app/(tabs)/ demo screens, components/, hooks/,
constants/theme.ts demo files, CLAUDE.md, AGENTS.md, .claude/. That's a
lot of files this project doesn't want.

Instead, use the blank TypeScript template, which gives you ONLY the
essentials (package.json, app.json, tsconfig.json, babel.config.js,
App.tsx, assets/, .gitignore) with no demo components/hooks/constants
and no app/(tabs) router demo at all:

    cd frontend\mobile
    npx create-expo-app@latest . --template blank-typescript

Then (optional cleanup, since we're switching to Expo Router instead of
the App.tsx entry point the blank template ships with):

    Remove-Item App.tsx
    (also remove index.ts/index.js if present -- check with `dir` first)

Then go back to the TRU_Connect root and run the generator:

    cd ..\..
    python generate_project_structure_phase_1.py --force --clean

The generator MERGES into package.json/app.json/tsconfig.json/.gitignore
(adds only what's missing, never touches your existing expo/react/
react-native versions or your real asset paths) and fully WRITES app/**
and src/** (those are entirely generator-owned). See
docs/04_DATABASE_DESIGN.txt and docs/05_BACKEND_API_SPECIFICATION.txt for
what the src/ architecture is modelled on.

================================================================================
7. THE .npmrc FILE AND WHY IT'S NOT OPTIONAL
================================================================================

frontend/mobile/.npmrc should contain exactly:

    legacy-peer-deps=true

Why: several packages in this dependency tree (most notably
lucide-react-native@0.469.0 as of this writing) declare a peerDependency
range that stops at React 18 (`^16.5.1 || ^17.0.0 || ^18.0.0`), even
though they work fine with React 19 in practice -- their peerDependencies
field just hasn't been updated yet. Without this setting, npm's strict
ERESOLVE check refuses to install anything, including when `npx expo
install --fix` runs its own internal `npm install` (it does NOT know
about a --legacy-peer-deps flag you type manually -- only a project-level
.npmrc is read automatically by every npm invocation, including ones
Expo's CLI triggers for you).

This is a live, currently-unresolved ecosystem issue (React 19 shipped
faster than some peerDependencies fields got updated) -- it is not a sign
that anything is actually broken.

8. TROUBLESHOOTING LOG (errors already hit on this project, and their fixes)
================================================================================

  ERROR: "ERESOLVE unable to resolve dependency tree" mentioning
  lucide-react-native and react@19.1.0
    FIX: create .npmrc with `legacy-peer-deps=true` (Section 7), then
    `npm install --legacy-peer-deps` once, then future installs just work.

  ERROR: "[BABEL]: Cannot find module 'react-native-worklets/plugin'"
    FIX: `npx expo install react-native-worklets` -- Reanimated 4 split
    its worklets engine into a separate package (Section 4.1).

  ERROR: "Cannot find module 'babel-preset-expo'"
    FIX: `npx expo install babel-preset-expo` (Section 4.3). Usually
    present by default in Expo templates; can go missing after several
    rounds of dependency-conflict installs.

  ERROR: 'Unable to resolve "expo-linking" from
  "node_modules/expo-router/build/views/Unmatched.js"'
    FIX: `npx expo install expo-linking` -- required internally by
    expo-router, not something app code imports directly (Section 4.1).

  General rule when something "doesn't seem to work" after a fix:
    run `npx expo start -c` (clear cache) before assuming the fix failed.

9. QUICK CHEAT SHEET
================================================================================

  Fresh machine, project already generated, node_modules missing:
      cd frontend/mobile
      npm install --legacy-peer-deps
      npx expo install --fix
      npx expo start -c

  Added a new package and something conflicts:
      npm install <package> --legacy-peer-deps
      (or npx expo install <package> if it's a native/Expo module)

  Something is bundling but crashing with "Cannot find module X":
      npx expo install X        (if X is a native/Expo package)
      npm install X --legacy-peer-deps   (if X is a plain JS package)
      npx expo start -c

  Full health check:
      npx expo-doctor

  Regenerate/update the app/** and src/** source code after re-running
  the generator (never destroys package.json/app.json settings):
      python generate_project_structure_phase_1.py --force
