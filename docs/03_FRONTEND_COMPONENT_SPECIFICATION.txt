================================================================================
                            TRU CONNECT
                FRONTEND COMPONENT SPECIFICATION
                          Document 03
================================================================================

Target Platform: React Native
Version: 1.0
Related Documents: 02_SYSTEM_UI_UX_SPECIFICATION.txt

Purpose: Define every reusable component in the TRU Connect React Native
component library. Every screen in the application must be composed from
these components rather than one-off, screen-specific implementations.

================================================================================
1. COMPONENT LIBRARY STRUCTURE
================================================================================

Components are organised into four groups:

    1. Authentication Components
    2. Business Components
    3. Supplier Components
    4. Shared Components

Each component below is defined by: Purpose, Props (conceptual, not code),
Visual States, and Usage Notes.

================================================================================
2. AUTHENTICATION COMPONENTS
================================================================================

2.1 LoginScreen
    Purpose: Capture credentials and authenticate an existing user.
    Contains: Email/username input, password input, "Continue with Google"
    action, "Forgot password" link, link to Register.
    States: default, validating, error (invalid credentials), loading.

2.2 RegisterScreen
    Purpose: Create a new account and capture initial role (Business or
    Supplier).
    Contains: Role selector, basic account fields, terms acceptance,
    "Continue with Google" action, link to Login.
    States: default, validating, error, loading.

2.3 GoogleAuthButton
    Purpose: Trigger Google OAuth flow.
    Props: onSuccess handler, onError handler, role context (business or
    supplier, for first-time registrations).
    States: default, loading, error.

2.4 RoleSelector
    Purpose: Let a first-time user choose Business or Supplier during
    registration or on the landing screen.
    Props: selectedRole, onSelect.
    States: unselected, business-selected, supplier-selected.

================================================================================
3. BUSINESS COMPONENTS
================================================================================

3.1 BusinessSummaryCard
    Purpose: Dashboard summary of the business's account (name, category,
    verification status).
    Props: businessName, category, verificationStatus.

3.2 SupplierCard
    Purpose: Represent a supplier in list/grid contexts (search results,
    nearby suppliers, saved suppliers).
    Props: supplierName, category, distance (optional), verificationStatus,
    ratingSummary (derived from Business Questions / statistics, not star
    rating — see Document 09), onPress.
    States: default, saved/bookmarked, unverified.

3.3 ProductCard
    Purpose: Represent a product in catalogue, search, or recommendation
    contexts.
    Props: productName, price, unit, supplierName, availabilityStatus,
    thumbnailImage, onPress.
    States: default, out-of-stock, on-promotion.

3.4 OrderCard (Business view)
    Purpose: Represent a single order in the business's order list.
    Props: orderId, supplierName, status (pending/accepted/completed/
    cancelled), totalAmount, orderDate, onPress.
    States: pending, accepted, completed, cancelled, delayed.

3.5 CategoryCard / Category Chips
    Purpose: Browse suppliers or products by category.
    Props: categoryName, icon, isSelected, onPress.

3.6 BusinessQuestionThread
    Purpose: Display and submit Business Questions beneath a product.
    Props: productId, questions (list of question + supplier response +
    timestamp), onSubmitQuestion.
    States: no questions yet (empty state), questions with pending
    response, questions with response.

3.7 DigitalBusinessProfileCard
    Purpose: Present the automatically generated business trust profile
    (see Document 07).
    Props: businessSince, ordersCount, suppliersCount, averageOrderValue,
    repeatSupplierRate, averagePaymentTime, businessGrowth, riskLevel.
    Usage Notes: Read-only. Data is generated entirely server-side; this
    component never accepts manual input for these fields.

================================================================================
4. SUPPLIER COMPONENTS
================================================================================

4.1 SupplierSummaryCard
    Purpose: Dashboard summary of the supplier's account.
    Props: supplierName, category, verificationStatus.

4.2 CustomerCard
    Purpose: Represent a business customer in enquiry or order contexts,
    respecting Business Privacy rules (Document 09).
    Props: displayName ("Verified Business" or "ABC Store (Verified)"),
    verificationStatus, lastInteractionDate, onPress.
    Usage Notes: Must never render full, unmasked business identity details
    beyond what the platform's privacy rules permit.

4.3 ProductManagementCard
    Purpose: Represent a product in the supplier's own catalogue management
    view, with edit/status controls.
    Props: productName, price, stockStatus, isPublished, onEdit, onToggle
    Availability.

4.4 OrderCard (Supplier view)
    Purpose: Represent a single incoming or historical order in the
    supplier's order list.
    Props: orderId, customerDisplayName, status, totalAmount, orderDate,
    onAccept, onReject, onPress.
    States: new/incoming, accepted, in-fulfilment, completed, cancelled.

4.5 BusinessPerformanceCard
    Purpose: Present supplier-facing performance statistics (see Document
    07 for underlying metrics).
    Props: activeSince, businessesServed, ordersCompleted, repeatCustomer
    Rate, averageResponseTime, responseRate, verificationStatus.

4.6 BusinessUpdateComposer
    Purpose: Allow a supplier to publish a Business Update.
    Props: updateType (new product / promotion / price update / hours /
    location / announcement), content, onPublish.

================================================================================
5. SHARED COMPONENTS
================================================================================

5.1 AppHeader
    Purpose: Persistent header used across top-level tab screens.
    Props: title, showNotificationIcon, showProfileIcon, onNotificationPress,
    onProfilePress.

5.2 SearchBar
    Purpose: Text-based search entry point for suppliers, products, or
    orders depending on context.
    Props: placeholder, value, onChangeText, onSubmit, onFilterPress.

5.3 BottomNavigation
    Purpose: Primary tab navigation, rendered conditionally based on
    authenticated role.
    Props: activeTab, role (business | supplier), onTabPress.

5.4 StatisticsCard
    Purpose: Generic single-metric display card used by both
    DigitalBusinessProfileCard and BusinessPerformanceCard.
    Props: label, value, trendDirection (optional), trendValue (optional).

5.5 NotificationCard
    Purpose: Represent a single notification in the notification list.
    Props: notificationType, message, timestamp, isRead, onPress.
    States: unread, read.

5.6 VerificationBadge
    Purpose: Consistent visual indicator of verified status, used across
    Business Cards, Supplier Cards, and profile headers.
    Props: isVerified.
    Usage Notes: Always paired with icon + text label, never colour alone
    (accessibility requirement, Document 02 Section 13).

5.7 CategoryChips
    Purpose: Horizontally scrollable filter/browse control.
    Props: categories (list), selectedCategory(ies), onSelect,
    multiSelect (boolean).

5.8 ActionButton
    Purpose: Generic button component supporting Primary, Secondary,
    Tertiary, and Destructive visual variants (Document 02, Section 8).
    Props: label, variant, onPress, isLoading, isDisabled.

5.9 EmptyState
    Purpose: Consistent placeholder for any list-based screen with no
    content.
    Props: icon, message, actionLabel (optional), onActionPress (optional).

5.10 LoadingState
    Purpose: Consistent skeleton-loading placeholder matching the shape of
    pending content (card skeleton, list skeleton, profile skeleton).
    Props: variant (card | list | profile), count.

5.11 Modal
    Purpose: Generic overlay container for short-lived focused tasks (e.g.
    filter selection, image preview).
    Props: isVisible, onClose, children.

5.12 Dialog
    Purpose: Confirmation prompt for destructive or high-consequence
    actions (Document 02, Section 2.4).
    Props: title, message, confirmLabel, cancelLabel, onConfirm, onCancel.

================================================================================
6. COMPONENT REUSE RULES
================================================================================

    1. No screen may implement its own one-off version of a component
       listed above; all variations must be expressed through props.
    2. Role-specific components (Business vs Supplier) must share the same
       underlying visual shell (card structure, spacing, typography) as
       defined in Document 02, differing only in content and available
       actions.
    3. Any new component required during development must be proposed as
       an addition to this document before implementation, to preserve a
       single, consistent component library as the codebase scales.
