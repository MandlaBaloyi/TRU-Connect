================================================================================
1. LIBRARY STRUCTURE
================================================================================

    src/components/ui/            Primitives (buttons, containers)
    src/components/cards/         Card components
    src/components/forms/         Form controls
    src/components/feedback/      Loading, empty, error, offline
    src/components/navigation/    Headers, tab bar

    src/features/<feature>/components/   Feature-specific components

Rule: a component used by more than one feature belongs in
src/components/. A component used by exactly one feature belongs to that
feature.

New:

4.4 MoneyInput
    Purpose: currency entry with numeric keypad, thousands formatting,
    and no ambiguity about decimals.
    Problem solved: money is entered constantly (orders, Loan Book) and
    is the highest-consequence field in the product to get wrong.
    Props: control, name, label, currency (default ZAR).

4.5 ContactPickerField
    Purpose: select a phone number from device contacts instead of typing
    it.
    Problem solved: typing a phone number is slow and error-prone, and
    adding a supplier or customer is the most common data-entry moment in
    the product (TP-059).
    Props: control, name, label, onManualEntry fallback.
    Note: requires a contacts permission; must degrade to manual entry
    if permission is declined.

4.6 QuantityStepper
    Purpose: increment/decrement quantity without keyboard entry.
    Problem solved: removes typing from the most repeated field in order
    placement.

5.5 SyncStatusBadge
    Purpose: show whether an individual item has reached the server.
    States: pending_sync, synced, sync_failed.
    Problem solved: a business must never believe an order was placed
    when it is still queued locally (Document 02, Section 12.3). This is
    a correctness-critical component, not decoration.
    Props: status, onRetry.

================================================================================
6. STATUS & DISPLAY COMPONENTS
================================================================================

6.1 StatusPill
    Purpose: one consistent representation of any order/delivery/payment
    status across both roles.
    Props: status, size.
    Rule: always renders icon + colour + text label, never colour alone.

6.2 MoneyText
    Purpose: one consistent money format everywhere.
    Props: amount, currency, emphasis (normal | outstanding | settled).
    Problem solved: inconsistent money formatting erodes trust in a
    product whose entire purpose is accurate records.

6.3 VerificationBadge
    Purpose: consistent verified indicator.
    Props: isVerified.

6.4 StatCard
    Purpose: single metric with label and optional trend.

6.5 SectionHeader
    Purpose: consistent section title with optional trailing action.

================================================================================
7. BUSINESS COMPONENTS
================================================================================

7.1 MySupplierCard   [was SupplierCard]
    Purpose: represent a supplier this business ALREADY trades with.
    Props: supplierName, category, isOnPlatform, isVerified,
           lastOrderDate, outstandingOrderCount, onPress.
    States: on-platform (orders flow digitally), off-platform (local
    record only, invite available).
    Note the change of meaning: this is a relationship, not a search
    result. There is no rating, no distance-ranking, and no promotional
    surface.

7.2 AddSupplierSheet
    Purpose: add an existing supplier in seconds.
    Problem solved: this is the first action a new business takes; it
    determines whether the product is adopted at all.
    Contains: name field, ContactPickerField, optional category,
    save action.
    Requirement: must be completable with minimal typing.

7.3 OrderQueueCard
    Purpose: one outstanding order requiring attention.
    Props: orderId, counterpartyName, status, totalAmount, placedAt,
           nextAction, syncStatus, onPress.
    Problem solved: replaces "scroll back through WhatsApp to find what
    is outstanding".

7.4 OrderCard
    Purpose: an order in history or list contexts.
    Props: orderId, counterpartyName, status, totalAmount, orderDate,
           onPress.

7.5 RepeatOrderButton
    Purpose: re-place a previous order in one action.
    Props: sourceOrderId, onPress.
    Problem solved: informal business ordering is highly repetitive;
    re-entering it every time is pure friction.

7.6 LoanBookEntryCard
    Purpose: one credit sale owed by a customer.
    Props: customerName, originalAmount, outstandingAmount, saleDate,
           isSettled, onPress.
    Rule: outstanding amount uses MoneyText with emphasis="outstanding".

7.7 LoanBookSummaryCard
    Purpose: total outstanding across all customers.
    Problem solved: a paper book cannot total itself. This single number
    is one of the most valuable things the product shows.

7.8 CustomerCard
    Purpose: a repeat customer of the business.
    Props: customerName, contactNumber, outstandingBalance, onPress.

================================================================================
9. COMPONENT RULES
================================================================================

    1. No screen may implement a one-off version of a component listed
       here; variation is expressed through props.
    2. Business and Supplier components share the same visual shell,
       differing only in content and available actions.
    3. Money is rendered only through MoneyText. Status is rendered only
       through StatusPill. No exceptions -- these carry correctness
       meaning, not just styling.
    4. Any new component must be added to this document before
       implementation (TP-066: Documentation Before Implementation).
