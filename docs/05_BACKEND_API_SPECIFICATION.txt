================================================================================
                            TRUCONNECT
                  BACKEND API SPECIFICATION
                          Document 05
================================================================================

Backend: Python 3.12, Flask, PostgreSQL, SQLAlchemy
Architecture: Modular Monolith, Domain-Driven, API-First (TP-034, TP-035)
Authentication: JWT (access + rotating refresh) + Google (planned)
Version: 3.0 (Constitution Alignment)

--------------------------------------------------------------------------------
CHANGES IN THIS VERSION
--------------------------------------------------------------------------------
REMOVED: all /questions and /products/{id}/questions endpoints
         (Business Questions removed from the product).
REMOVED: /wallet/* and /credit/* future endpoints
         (TRUConnect is not a money holder or lender; these belong to
         future TruePoint products).
RENAMED: supplier discovery endpoints -> /businesses/me/suppliers
         (managing EXISTING relationships).
ADDED:   Loan Book, Customers, Order Queue, payment events, delivery
         confirmation, supplier tiers, offline sync.

Section 5.1 (Authentication) documents endpoints EXACTLY AS IMPLEMENTED.
No change to any implemented endpoint is proposed anywhere in this
document (TP-043: Backward Compatibility).

================================================================================
1. CONVENTIONS
================================================================================

    - Versioned base path: /api/v1
    - JWT bearer authentication on protected endpoints
    - Authorization via RBAC role/permission checks, not hard-coded roles
    - Pagination on all list endpoints
    - ISO 8601 / UTC timestamps
    - Consistent response envelope:

        Success: {"success": true,  "message": "...", "data": {}}
        Failure: {"success": false, "message": "...", "errors": []}

    - Idempotency: any endpoint that can be retried by offline sync
      accepts a client_generated_id and returns the original result on
      duplicate submission rather than creating a second record.

5.1 AUTHENTICATION  [IMPLEMENTED -- VERIFIED AGAINST RUNNING CODE]
================================================================================

    POST   /auth/register              Create account. Role ("business" |
                                        "supplier") in payload. Minimal
                                        fields only.
    POST   /auth/login                 Email + password. Case-insensitive
                                        email. Returns access + refresh.
    POST   /auth/refresh               Refresh-token rotation: revokes the
                                        presented token, returns a NEW
                                        access AND refresh token pair.
    GET    /auth/me                    Current authenticated user.
    POST   /auth/logout                Revokes refresh token(s).
    POST   /auth/phone/request-otp     Issues an OTP to a destination.
                                        Enumeration-safe.
    POST   /auth/phone/verify-otp      Verifies an OTP. Expiry, attempt
                                        limiting, single use enforced.
    POST   /auth/forgot-password       Enumeration-safe; identical
                                        response whether or not the email
                                        exists.
    POST   /auth/reset-password        Single-use token; revokes all
                                        refresh tokens on success.

    Planned, additive: /auth/google, /auth/me/roles,
    /auth/me/login-history, /admin/users/{id}/roles.

--------------------------------------------------------------------------------
5.7.1 Offline Sync
--------------------------------------------------------------------------------

    POST   /sync/batch                        Submit a batch of queued
                                              offline actions. Every item
                                              carries a
                                              client_generated_id. Returns
                                              per-item result: applied,
                                              duplicate, or rejected with
                                              reason.
    GET    /sync/status                       Server view of recently
                                              submitted client actions

    Duplicate submission MUST return the original result, never create a
    second record. This is a correctness requirement: sync retries are
    normal, and a duplicated order becomes a duplicated real-world
    delivery.

================================================================================
6. ROLE-BASED ACCESS SUMMARY
================================================================================

    Business only:      place/cancel orders, manage my suppliers, Loan
                        Book, customers, own profile and documents.
    Supplier only:      accept/decline/dispatch orders, issue payment
                        references, manage delivery regions and hours.
    Supplier Pro only:  product catalogue, staff, reporting.
    Supplier Ent. only: teams, API keys, advanced reporting.
    Either party:       delivery confirmation, payment events on a shared
                        order.
    Admin only:         verification review, role management, audit logs,
                        system settings.

All write operations validate resource ownership in addition to
authentication.

================================================================================
7. EXPLICITLY OUT OF SCOPE
================================================================================

TRUConnect exposes NO endpoints for:
    - Holding, transferring, or escrowing funds
    - Wallet balances
    - Credit applications, loan origination, or repayment collection

These belong to future TruePoint products and will consume TRUConnect's
trust outputs through platform APIs.
