=========================================================
TRU CONNECT
MONEY ENGINE ARCHITECTURE
Engineering Specification v1.0
=========================================================

PURPOSE

Money Modules are any platform feature responsible for
creating, modifying, moving, calculating or storing money.

These modules require the highest engineering standards
because even a one-cent error is unacceptable.

Money Modules DO NOT become a separate domain.

Instead:

• Every feature remains inside its own business domain.
• Every money feature uses the Shared Money Engine.

This preserves domain ownership while guaranteeing
consistent financial behaviour across the platform.

=========================================================
ENGINE RESPONSIBILITIES
=========================================================

CORE

Responsible for defining money itself.

• Money object
• Currency
• Precision
• Constants
• Exceptions

----------------------------------------

CALCULATIONS

Responsible for every financial calculation.

Examples

• Addition

• Subtraction

• Allocation

• Interest

• Fees

• Tax

• Discounts

• Settlement calculations

No feature performs its own calculations.

----------------------------------------

FORMATTING

Responsible for converting money between
system format and human format.

Examples

5000

↓

R50.00

Supports

• Currency symbols

• Thousand separators

• Parsing user input

• JSON serialization

----------------------------------------

VALIDATION

Responsible for validating all money values.

Rejects

• Negative amounts

• Invalid precision

• Overflow

• Invalid currency

• Business rule violations

----------------------------------------

RECEIPTS

Responsible for generating secure receipts.

Includes

• Receipt builder

• Receipt references

• QR security

• Digital signing

• Receipt verification

Future

• QR verification portal

• Tamper detection

=========================================================
ENGINEERING PRINCIPLES
=========================================================

Business logic stays inside its feature.

Money logic NEVER gets duplicated.

Every financial feature imports the Shared Money Engine.

Examples

Loan Book

↓

from shared.money.calculations.allocation import allocate_payment

----------------------------------------

TRU Wallet

↓

from shared.money.calculations.arithmetic import add_money

----------------------------------------

Supplier Payments

↓

from shared.money.validation.validator import validate_amount

----------------------------------------

Receipts

↓

from shared.money.receipts.receipt_builder import build_receipt

----------------------------------------

Formatting

↓

from shared.money.formatting.formatter import format_money

=========================================================
ARCHITECTURE PHILOSOPHY
=========================================================

Features own the business logic.

The Shared Money Engine owns financial behaviour.

Every financial feature behaves consistently because
they all use the same Money Engine.

This eliminates duplicated calculations, inconsistent
rounding, formatting differences, validation drift,
and receipt generation inconsistencies across the
entire TruConnect platform.
