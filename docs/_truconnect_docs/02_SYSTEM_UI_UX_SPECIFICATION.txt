1. DESIGN PRINCIPLES
================================================================================

1.1 Simple First
    Every screen should communicate its purpose within one glance. Avoid
    decorative complexity that does not aid comprehension or action.

1.2 Trust by Design
    Verification badges, supplier statistics, and transparent business
    information should be visually prominent, never buried in secondary
    screens.

1.3 Mobile First & Low-Bandwidth Aware
    Layouts must remain legible and usable on small, lower-end Android
    devices, with graceful handling of slow or intermittent connectivity
    (skeleton loading states, cached content, optimistic UI where safe).

1.4 Consistency Across Roles
    Business and Supplier experiences should feel like the same product
    wearing two hats — shared visual language, shared components, distinct
    content.

1.5 Accessibility First
    Legible type sizes, adequate touch targets, sufficient colour contrast,
    and screen-reader compatibility are baseline requirements, not
    enhancements.

================================================================================
2. MOBILE UX GUIDELINES
================================================================================

2.1 Navigation Pattern
    Bottom tab navigation (5 tabs) is the primary navigation pattern for
    both roles. Stack navigation is used within each tab for drill-down
    flows (e.g. Suppliers tab -> Supplier Profile -> Product Detail).

2.2 Touch Targets
    Minimum touch target size: 44x44 density-independent pixels (dp),
    consistent with platform accessibility guidelines.

2.3 Loading & Empty States
    Every list-based screen must define both a Loading State and an Empty
    State (see Document 03, Shared Components). Never present a blank
    screen while data is pending or absent.

2.4 Feedback & Confirmation
    Destructive or high-consequence actions (cancel order, reject order,
    delete document) require explicit confirmation via a Dialog component.

2.5 Offline Tolerance
    Core read operations (viewing cached supplier profiles, past orders)
    should degrade gracefully offline, with a persistent but unobtrusive
    connectivity indicator.

================================================================================
3. NAVIGATION STRUCTURE
================================================================================

3.1 Business Navigation
    Tab bar icons and labels:
        Home | Business | Suppliers | Orders | More

3.2 Supplier Navigation
    Tab bar icons and labels:
        Home | Products | Orders | Customers | More

3.3 Header Behaviour
    Each top-level tab uses a persistent App Header (see Document 03)
    showing context (page title, notification icon, profile icon). Detail
    screens use a back-navigation header with contextual title.

================================================================================
4. TYPOGRAPHY
================================================================================

A single type scale is used across both experiences.

    Display        — 28sp / Bold      — Dashboard greetings, key totals
    Heading 1       — 22sp / Semibold  — Screen titles
    Heading 2       — 18sp / Semibold  — Section headers, card titles
    Body            — 15sp / Regular   — Primary content text
    Body Small      — 13sp / Regular   — Secondary / supporting text
    Caption         — 11sp / Medium    — Labels, timestamps, badges

Font family: a single system-safe sans-serif font family should be selected
at implementation time and applied consistently (e.g. via a shared theme
provider) rather than mixed across screens.

Line height should be set at approximately 1.4x font size for body text to
preserve readability on small screens.

================================================================================
5. COLOR PALETTE
================================================================================

The palette is organised into functional roles rather than fixed hex values,
so that theming (including future dark mode) can be layered on without
redesign.

    Primary          — Brand colour; primary actions, active tab, key CTAs
    Primary Dark      — Pressed / active states of primary elements
    Secondary        — Supporting brand colour; secondary actions, highlights
    Success           — Verified status, completed orders, positive trends
    Warning           — Pending status, low stock, attention-needed states
    Danger            — Cancelled orders, destructive actions, errors
    Neutral 900–100   — Text and surface greyscale range (dark to light)
    Surface           — Card and screen background
    Border            — Dividers, card outlines, input borders

Verification badges consistently use the Success colour role; pending
states consistently use the Warning colour role, across both business and
supplier experiences, to build recognisable visual trust cues.

================================================================================
6. COMPONENTS (SUMMARY)
================================================================================

Full technical definitions live in Document 03. This document defines their
visual and interaction rules:

    - App Header — persistent, contextual, houses notification and profile
      access.
    - Search Bar — persistent at top of discovery-oriented screens.
    - Bottom Navigation — 5-tab, role-dependent.
    - Business Card / Supplier Card / Product Card / Order Card / Customer
      Card — consistent card shell (rounded corners, elevation, consistent
      padding) with role-specific content.
    - Statistics Card — used for Digital Business Profile and Supplier
      Performance; emphasises a single metric with supporting label and
      trend indicator.
    - Notification Card — unread/read visual states.
    - Verification Badge — small icon + label, Success colour role, used
      consistently across all card types.
    - Category Chips — horizontally scrollable, single-select or
      multi-select depending on context.
    - Action Button — primary, secondary, and tertiary visual variants.
    - Empty State — icon + short message + optional call-to-action.
    - Loading State — skeleton placeholders matching the shape of the
      content being loaded, rather than a generic spinner, wherever
      feasible.

================================================================================
7. CARDS
================================================================================

All card components share:
    - Consistent corner radius across the app (single value, defined once
      in the shared theme).
    - Consistent elevation/shadow treatment.
    - Consistent internal padding and spacing rhythm (see Section 9).
    - A predictable content hierarchy: primary identifier (name/title) at
      top, supporting metadata in the middle, action or status indicator
      at the bottom or trailing edge.

================================================================================
8. BUTTONS
================================================================================

    Primary Button    — Solid fill, Primary colour, used for the single
                         most important action on a screen.
    Secondary Button   — Outlined, Primary colour border and text, used for
                         supporting actions.
    Tertiary Button    — Text-only, used for low-emphasis actions (e.g.
                         "Skip", "Not now").
    Destructive Button — Danger colour role, used only for actions that
                         cancel, reject, or delete.

Only one Primary Button should appear per screen or per card context to
preserve clear visual hierarchy.

================================================================================
9. FORMS
================================================================================

    - Inputs use a consistent height, border, and focus-state treatment.
    - Labels are always visible above the input (not placeholder-only),
      to support usability for less digitally experienced users.
    - Validation errors appear inline, beneath the relevant field, in the
      Danger colour role.
    - Multi-step forms (e.g. business registration, product creation) use
      a visible step indicator.

================================================================================
10. ICONS
================================================================================

    - A single icon set is used throughout the application for visual
      consistency (line-style icons recommended for clarity at small
      sizes).
    - Navigation icons always pair with text labels; icons are never used
      alone for primary navigation, to support first-time and less
      digitally experienced users.

================================================================================
11. LAYOUT & SPACING
================================================================================

A single spacing scale should be used throughout (expressed as multiples of
a base unit, e.g. 4dp):
    xs = 4dp, sm = 8dp, md = 16dp, lg = 24dp, xl = 32dp

    - Screen horizontal padding: md (16dp) as a baseline.
    - Vertical spacing between stacked cards: sm–md (8–16dp).
    - Section spacing (between major dashboard sections): lg (24dp).

================================================================================
12. ANIMATIONS
================================================================================

Animations should be purposeful and brief (150–250ms for most transitions),
supporting comprehension rather than decoration:

    - Screen transitions: standard platform-native push/pop and tab-switch
      animations.
    - Loading skeletons: subtle shimmer, not spinners, for card-shaped
      content.
    - Status changes (e.g. order accepted): brief, subtle confirmation
      animation on the relevant card or badge.
    - Avoid animation on data that updates frequently (e.g. statistics
      counters) to prevent visual noise.

================================================================================
13. ACCESSIBILITY
================================================================================

    - Minimum contrast ratio of 4.5:1 for body text against its background.
    - All interactive elements must have accessible labels for screen
      readers (React Native accessibilityLabel).
    - Dynamic font scaling (OS-level text size settings) must be supported
      without breaking layout.
    - Colour must never be the sole indicator of status (e.g. verification
      badges pair colour with an icon and text label, not colour alone).
