===========================================================================
BACKLOG — WHAT IS OUTSTANDING, AND HOW URGENT
===========================================================================

Started 2026-09-11. An INDEX, not a plan. Each line says what and why
now; the reasoning lives in the document named beside it.

WHY THIS FILE EXISTS. Working on one thing surfaces three others --
writing the verification plan revealed that the media path would make
ID documents world-readable; building the curtain revealed that 325
test fixtures encoded an assumption; testing a banner revealed there
was no approval email at all. None of that was foreseeable from the
start, and none of it belonged in the task that found it. An idea
arriving mid-task needs somewhere to go that is not somebody's memory.

  ─────────────────────────────────────────────────────────────────────
  THE TRIAGE QUESTION IS NOT "IS THIS A GOOD IDEA".
  Almost everything here is. It is: DOES WAITING MAKE IT COST MORE?
  ─────────────────────────────────────────────────────────────────────

That is the only thing the two sections below distinguish. A trigger
("the first supplier who asks for a second login") beats a date,
because a date slips quietly and a trigger cannot.

HOW TO USE IT. Add a line when something surfaces; delete it when it
ships. If an entry needs more than two lines, it needs a document, and
this file should point at that document instead.


===========================================================================
A — GETS MORE EXPENSIVE THE LONGER WE WAIT
===========================================================================

These are the only entries with a claim on the present.

  A1  IDEMPOTENCY KEYS ON POST                          V2_13 §3.1
      An ERP times out and retries -- correctly, since it cannot know
      whether we processed it -- and we create a second product.
      WHY NOW: the habit is the expensive part, not the table. Two
      years of write endpoints built without one means revisiting
      every single endpoint and re-deciding what "the same request"
      means for each.

  A2  AN EVENT LOG FOR STOCK ORDERS                     V2_13 §3.2
      network/orders/models/ has stock_order and stock_order_payment
      and no event record; the business's own books have two
      (LoanHistoryEvent, OrderHistoryEvent).
      WHY NOW: webhooks replay from an event stream, and the rows
      cannot be backfilled for history never recorded. Also answers
      "why did this order change?" today, which is a support question
      currently answered by inference.

  A3  THE ORIGIN OF A WRITE                             V2_13 §3.3
      No `source` (APP / IMPORT / API) on stock, price or product
      writes.
      WHY NOW: a column added later starts null for every existing
      row, and no analysis recovers where a number came from two years
      ago. Useful immediately: "how many of this supplier's prices were
      typed by hand?"

  A4  ACCOUNT DELETION DOES NOT WORK                    V2_07, CLEANUP
      Found 2026-09-08. NO ACTION foreign keys across ten tables mean
      deleting an account fails partway.
      WHY NOW: this one is POPIA-adjacent -- a legal obligation to
      erase data we cannot currently honour. It also gets harder with
      every table added, and tables are being added.
